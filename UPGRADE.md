# Upgrading from Curator v3 to v4

This guide will walk you through upgrading from Filament Curator v3 to v4. This is a major version upgrade that includes significant breaking changes due to the upgrade from Filament v3 to v4 and Tailwind CSS v3 to v4.

## Requirements

Before upgrading, ensure your project meets these requirements:

- PHP 8.2 or higher
- Laravel 11.28 or higher (required by Filament 4)
- Filament 4.0 or higher
- Tailwind CSS 4.0 or higher

## Overview of Major Changes

Curator v4 brings significant architectural improvements and breaking changes:

### Framework Upgrades
- **Filament**: v3.x → v4.0+
- **Tailwind CSS**: v3.x → v4.x
- **Asset Management**: Complete overhaul using Tailwind 4's new system

### Configuration Restructuring
- **Database table renamed**: `media` → `curator` (requires migration or model override)
- Flattened config structure reorganized into nested groups
- Many config keys renamed or relocated
- New required environment variables

### Installation Simplification
- Removed cropper.js dependency (cropper.css no longer needed)
- Curator's component CSS still required via `@import`
- Streamlined asset registration (CSS no longer registered in ServiceProvider)

### Code Architecture
- New manager classes for better organization
- Facade pattern introduced
- Enums for type safety
- DTOs for data transfer

## Step-by-Step Upgrade Guide

### Step 1: Update Composer Dependencies

Update your `composer.json`:

```bash
composer require awcodes/filament-curator:^4.0 filament/filament:^4.0
```

### Step 2: Handle Database Table Name Change (CRITICAL)

**Breaking Change**: Curator v4 changes the database table name from `media` to `curator`.

You have **two options** to handle this:

#### Option 1: Rename Your Database Table (Recommended)

Rename the existing `media` table to `curator`:

```php
use Illuminate\Database\Migrations\Migration;
use Illuminate\Support\Facades\Schema;

return new class extends Migration
{
    public function up(): void
    {
        Schema::rename('media', 'curator');
    }

    public function down(): void
    {
        Schema::rename('curator', 'media');
    }
};
```

Run the migration:

```bash
php artisan make:migration rename_media_table_to_curator
# Add the code above, then:
php artisan migrate
```

#### Option 2: Override the Table Name in Your Model

If you cannot rename the table, extend the Media model and override the table name:

```php
// app/Models/Media.php
namespace App\Models;

use Awcodes\Curator\Models\Media as CuratorMedia;

class Media extends CuratorMedia
{
    protected $table = 'media'; // Keep using 'media' table
}
```

Then update your `config/curator.php`:

```php
return [
    'model' => \App\Models\Media::class,
    // ... rest of config
];
```

> **Note**: The table structure itself hasn't changed - only the table name. No schema migration is needed.

### Step 3: Remove cropper.js Dependency

Curator v4 no longer requires cropper.js. Remove it from your `package.json`:

```bash
npm uninstall cropperjs
```

### Step 4: Update Theme CSS Files (CRITICAL)

This is the most critical change due to Tailwind 4's new CSS-first architecture.

#### How Tailwind 4 Works in Filament

Tailwind 4 fundamentally changed how it's configured:
- **v3**: Used `tailwind.config.js` with a `content: []` array
- **v4**: Uses CSS-first configuration with `@source` directives directly in your CSS file
- **No more config file**: Filament 4 doesn't use `tailwind.config.js` by default
- **Vite integration**: Tailwind is loaded via `@tailwindcss/vite` plugin in `vite.config.js`

#### Update CSS Imports

In your theme's CSS file (e.g., `resources/css/filament/admin/theme.css`):

1. **Remove the cropper.js import** (no longer needed):

```css
/* REMOVE THIS */
@import '<path-to-node-modules>/cropperjs/dist/cropper.css';
```

2. **Keep or add the Curator CSS import** (required for component styles):

```css
/* KEEP THIS - Required for .curator-picker-grid, .checkered, and other component styles */
@import '../../../../vendor/awcodes/filament-curator/resources/css/plugin.css';
```

> **Why is this CSS still needed?** Curator's `plugin.css` contains essential component styles (grid layouts, checkered backgrounds, modal customizations) that cannot be generated by Tailwind utilities alone. These use CSS custom properties, complex selectors, and pseudo-elements.

#### Add Tailwind 4 @source Directive

Your final theme CSS should look like this:

```css
@import '../../../../vendor/filament/filament/resources/css/theme.css';
@import '../../../../vendor/awcodes/filament-curator/resources/css/plugin.css';

@source '../../../../vendor/awcodes/filament-curator/resources/**/*.blade.php';
@source '../../../../app/Filament/**/*';
@source '../../../../resources/views/filament/**/*';
```

> **Why these changes?**
> - The `@import` for Curator's CSS provides essential component styles that Tailwind cannot generate
> - The `@source` directive tells Tailwind 4 to scan Curator's Blade files for utility classes
> - Together, they ensure both custom component styles and Tailwind utilities work correctly

#### No tailwind.config.js Needed

**Important**: Filament 4 with Tailwind 4 does **not** use `tailwind.config.js` by default. If you have one from Filament 3, you can keep it or remove it - Tailwind 4 uses CSS-first configuration.

All configuration is now done directly in your theme CSS file using directives like `@source` and `@theme`.

#### Verify Vite Configuration

Ensure your `vite.config.js` includes the Tailwind Vite plugin:

```javascript
import { defineConfig } from 'vite'
import laravel from 'laravel-vite-plugin'
import tailwindcss from '@tailwindcss/vite'

export default defineConfig({
    plugins: [
        laravel({
            input: [
                'resources/css/app.css',
                'resources/js/app.js',
                'resources/css/filament/admin/theme.css', // Your custom theme
            ],
            refresh: true,
        }),
        tailwindcss(), // ← This is required for Tailwind 4
    ],
})
```

If `tailwindcss()` is missing, install it:

```bash
npm install -D @tailwindcss/vite
```

### Step 5: Rebuild Your Assets

After updating your theme files:

```bash
npm run build
php artisan filament:assets
php artisan optimize:clear
```

### Step 6: Update Configuration File

Publish the new config file (this will overwrite your existing one, so **backup first**):

```bash
# Backup your current config
cp config/curator.php config/curator.php.backup

# Publish new config
php artisan vendor:publish --tag="curator-config" --force
```

#### Configuration Migration Guide

The configuration structure has been completely reorganized. Here's how to migrate your settings:

##### Core Settings

| v3 Config Key | v4 Config Key | Notes |
|---------------|---------------|-------|
| `disk` | `default_disk` | Now uses `env('CURATOR_DEFAULT_DISK')` |
| `visibility` | `default_visibility` | Renamed for clarity |
| `directory` | Removed | Managed through path generators |
| `model` | `model` | Unchanged |
| `path_generator` | `path_generator` | Unchanged |
| `should_preserve_filenames` | Removed | Set per-field now |
| `should_register_navigation` | `resource.navigation.should_register` | Nested structure |
| `should_check_exists` | Removed | Always enabled |

##### Feature Flags

v4 introduces a new `features` section:

```php
// v3: No explicit feature flags

// v4: New feature flags
'features' => [
    'curations' => true,
    'file_swap' => true,
    'directory_restriction' => false,
    'tenancy' => [
        'enabled' => false,
        'relationship_name' => null,
    ],
],
```

##### Resource Configuration

| v3 Config Key | v4 Config Key |
|---------------|---------------|
| `resources.label` | `resource.label` |
| `resources.plural_label` | `resource.plural_label` |
| `resources.navigation_group` | `resource.navigation.group` |
| `resources.navigation_icon` | `resource.navigation.icon` |
| `resources.navigation_sort` | `resource.navigation.sort` |
| `resources.navigation_count_badge` | `resource.navigation.should_show_badge` |
| `resources.resource` | `resource.resource` |
| `resources.cluster` | Removed |

##### New Configuration Keys

v4 adds several new configuration options:

```php
// Required: Glide security token
'glide_token' => env('CURATOR_GLIDE_TOKEN'),

// New: URL provider for custom URL generation
'url_provider' => Awcodes\Curator\Providers\GlideUrlProvider::class,

// New: Resource structure
'resource' => [
    'default_layout' => 'grid', // or 'list'
    'pages' => [
        'create' => Awcodes\Curator\Resources\Media\Pages\CreateMedia::class,
        'edit' => Awcodes\Curator\Resources\Media\Pages\EditMedia::class,
        'index' => Awcodes\Curator\Resources\Media\Pages\ListMedia::class,
    ],
    'schemas' => [
        'form' => Awcodes\Curator\Resources\Media\Schemas\MediaForm::class,
    ],
    'tables' => [
        'table' => Awcodes\Curator\Resources\Media\Tables\MediaTable::class,
    ],
],
```

##### Removed Configuration Keys

These v3 config keys have been removed in v4:

- `accepted_file_types` - Now handled by field-level configuration
- `cloud_disks` - Automatically detected
- `cropper.check_cross_origin` - Cropper removed
- `image_crop_aspect_ratio` - Set per-field
- `image_resize_mode` - Set per-field
- `image_resize_target_height` - Set per-field
- `image_resize_target_width` - Set per-field
- `is_limited_to_directory` - Use `features.directory_restriction`
- `is_tenant_aware` - Use `features.tenancy.enabled`
- `tenant_ownership_relationship_name` - Use `features.tenancy.relationship_name`
- `max_size` - Set per-field
- `min_size` - Set per-field
- `multi_select_key` - Removed
- `tabs.display_curation` - Use plugin method `curations()`
- `tabs.display_upload_new` - Removed
- `table.layout` - Use `resource.default_layout`

### Step 7: Generate Glide Token

v4 requires a secure token for Glide image serving. Generate one:

```bash
php artisan curator:token
```

This will add `CURATOR_GLIDE_TOKEN` to your `.env` file.

### Step 8: Update Plugin Registration

If you're using Filament Panels, update your plugin registration:

#### v3 Plugin Registration

```php
use Awcodes\Curator\CuratorPlugin;

public function panel(Panel $panel): Panel
{
    return $panel
        ->plugins([
            CuratorPlugin::make()
                ->label('Media')
                ->pluralLabel('Media')
                ->navigationIcon('heroicon-o-photo')
                ->navigationGroup('Content')
                ->navigationSort(3)
                ->navigationCountBadge()           // ❌ Removed
                ->registerNavigation(false)
                ->defaultListView('grid')          // ❌ Removed
                ->resource(\App\Filament\Resources\CustomMediaResource::class), // ❌ Removed
        ]);
}
```

#### v4 Plugin Registration

```php
use Awcodes\Curator\CuratorPlugin;

public function panel(Panel $panel): Panel
{
    return $panel
        ->plugins([
            CuratorPlugin::make()
                ->label('Media')
                ->pluralLabel('Media')
                ->navigationIcon('heroicon-o-photo')
                ->navigationGroup('Content')
                ->navigationSort(3)
                ->showBadge(true)               // ✅ Renamed from navigationCountBadge()
                ->registerNavigation(true)
                ->curations(true)               // ✅ New: Control curation feature
                ->fileSwap(true),               // ✅ New: Control file swap feature
        ]);
}
```

#### Plugin Method Changes

| v3 Method | v4 Equivalent | Notes |
|-----------|---------------|-------|
| `navigationCountBadge()` | `showBadge()` | Renamed |
| `defaultListView()` | Removed | Set in config: `resource.default_layout` |
| `resource()` | Removed | Set in config: `resource.resource` |
| `navigationLabel()` | Removed | Use `label()` or `pluralLabel()` |
| - | `curations()` | New: Enable/disable curations |
| - | `fileSwap()` | New: Enable/disable file swapping |

### Step 9: Update Form Components

The `CuratorPicker` component has some minor changes:

#### Import Changes

```php
// v3
use Filament\Forms\Components\Actions\Action;

// v4
use Filament\Actions\Action;
```

#### Default Values Changed

```php
// v3 defaults
CuratorPicker::make('image')
    ->size('md')              // String
    ->color('primary');       // Default color

// v4 defaults
CuratorPicker::make('image')
    ->size(Size::Medium)      // Enum
    ->color('gray');          // New default color
```

#### Removed Methods

These methods have been removed from `CuratorPicker` in v4:

- `typeColumn()` - Use at model level
- `typeValue()` - Use at model level

All other methods remain compatible.

### Step 10: Update Custom Components (If Any)

If you've extended Curator's components:

#### Size Parameter

```php
// v3
->size('sm'|'md'|'lg')

// v4
use Filament\Support\Enums\Size;
->size(Size::Small|Size::Medium|Size::Large)
```

#### Width Parameter

```php
// v4 adds Width enum support
use Filament\Support\Enums\Width;
->width(Width::Full)
```

### Step 11: Update Curation Presets

The `CurationPreset` class structure has changed slightly.

#### v3 Curation Preset

```php
use Awcodes\Curator\Curations\CurationPreset;

class ThumbnailPreset extends CurationPreset
{
    public function getKey(): string
    {
        return 'thumbnail';
    }

    public function getLabel(): string
    {
        return 'Thumbnail';
    }

    public function getWidth(): int
    {
        return 200;
    }

    public function getHeight(): int
    {
        return 200;
    }

    public function getFormat(): string
    {
        return 'webp';
    }

    public function getQuality(): int
    {
        return 60;
    }
}
```

#### v4 Curation Preset (No Changes Needed)

The `CurationPreset` API remains the same in v4, so your existing presets should work without modification. However, the config registration changed:

```php
// v3 config
'curation_presets' => [
    \App\Curations\ThumbnailPreset::class,
],

// v4 config - REMOVED from config!
// Now use CurationManager facade or register via service provider
```

> **Note**: Curation preset registration has moved from config to the `CurationManager` class.

### Step 12: Update Glide Server Factories (If Customized)

If you have a custom Glide server factory, the interface hasn't changed, but be aware:

```php
// Both v3 and v4 use the same interface
use Awcodes\Curator\Glide\Contracts\ServerFactory;

class CustomServerFactory implements ServerFactory
{
    public function getFactory(): ServerFactory | Server

        // Implementation remains the same
    }

```

## Breaking Changes Summary

### Database Changes

- **Table name changed**: `media` → `curator` (requires migration or model override)

### Removed Features

- **cropper.js dependency**: No longer needed
- **CSS import directives**: Replaced by Tailwind 4 @source
- **Type column/value methods**: Managed at model level now
- **Tab display config**: Use plugin methods instead
- **Multi-select key config**: Removed
- **Many config-level validation settings**: Now set per-field

### Renamed/Relocated

- `disk` → `default_disk`
- `visibility` → `default_visibility`
- `navigationCountBadge()` → `showBadge()`
- Config structure: flat → nested (`resource`, `features`)
- Table name: `media` → `curator`

### New Requirements

- **CURATOR_GLIDE_TOKEN**: Required environment variable
- **Tailwind 4 @source directive**: Must be added to theme
- **Manager classes**: New architecture for better organization

### Behavior Changes

- **Tailwind 4 CSS-first**: No `tailwind.config.js`, uses `@source` directives in CSS
- **Asset compilation**: Tailwind 4 auto-compiles from Blade file scans
- **Vite plugin**: Uses `@tailwindcss/vite` instead of PostCSS
- **Default picker color**: `primary` → `gray`
- **Asset registration**: Only Alpine component, no CSS/JS registration in ServiceProvider
- **Tenancy**: Now optional via feature flag
- **Directory restriction**: Now optional via feature flag

## Troubleshooting

### Media Grid Not Displaying

**Problem**: The media picker shows a blank/broken grid.

**Solution**:
1. Verify `@source` directive is in your theme CSS
2. Rebuild assets: `npm run build`
3. Clear caches: `php artisan optimize:clear`
4. Check browser console for CSS errors

### Glide Images Not Loading

**Problem**: Images return 403 or show as broken.

**Solution**:
1. Verify `CURATOR_GLIDE_TOKEN` is set in `.env`
2. Run: `php artisan curator:token` if missing
3. Clear config cache: `php artisan config:clear`

### Plugin Not Registered

**Problem**: Curator menu item not showing.

**Solution**:
1. Check plugin registration in Panel provider
2. Verify config: `resource.navigation.should_register` is `true`
3. Clear cache: `php artisan optimize:clear`

### Configuration Errors

**Problem**: Errors about missing config keys.

**Solution**:
1. Backup your old config
2. Republish: `php artisan vendor:publish --tag="curator-config" --force`
3. Manually migrate your custom settings to the new structure

### TypeScript/Build Errors

**Problem**: npm build fails after upgrade.

**Solution**:
1. Remove cropper.js: `npm uninstall cropperjs`
2. Delete `node_modules` and `package-lock.json`
3. Reinstall: `npm install`
4. Build: `npm run build`

## New Features in v4

While this is primarily a breaking changes guide, v4 also introduces several new features:

### Feature Flags

Control Curator features via configuration:

```php
'features' => [
    'curations' => true,
    'file_swap' => true,
    'directory_restriction' => false,
    'tenancy' => [
        'enabled' => false,
        'relationship_name' => null,
    ],
],
```

### Manager Classes

Better code organization with dedicated managers:

- `CuratorManager`: Core Curator functionality
- `CurationManager`: Curation presets and operations
- `GlideManager`: Glide server configuration

### Facades

New facades for easier access:

```php
use Awcodes\Curator\Facades\Curator;
use Awcodes\Curator\Facades\Curation;
use Awcodes\Curator\Facades\Glide;

// Example usage
$media = Curator::getMedia($id);
$curation = Curation::getCuration($mediaId, 'thumbnail');
```

### Enums

Type-safe enums for better developer experience:

- `MimeType`: Media MIME types
- `CurationFormats`: Available curation formats
- `PreviewableExtensions`: File extensions that can be previewed
- `AudioExtensions`: Audio file extensions
- `VideoExtensions`: Video file extensions

### DTOs

Data Transfer Objects for cleaner data handling:

- `MediaDTO`: Structured media data

## Recommended Upgrade Path

For the smoothest upgrade experience:

1. **Upgrade on a separate branch**: Don't upgrade on main/production
2. **Test thoroughly**: Create a test environment first
3. **Backup your database**: Always backup before running migrations
4. **Document customizations**: Note any custom Curator modifications you've made
5. **Review all changes**: Read this guide completely before starting
6. **Allocate time**: Budget 2-4 hours for a complete upgrade depending on customizations

## Conclusion

Curator v4 brings significant improvements in code organization, performance, and alignment with Filament v4 and Tailwind v4. While the upgrade requires careful attention to breaking changes, the result is a more maintainable and performant media management system.

The most critical changes to watch for are:

1. **Database table name**: Changed from `media` to `curator` (requires migration or model override)
2. **Asset management**: Completely different with Tailwind 4
3. **Configuration structure**: Heavily reorganized
4. **Glide token**: New security requirement
5. **Plugin methods**: Several renamed or removed

Follow this guide step by step, test thoroughly, and you'll have a successful upgrade to Curator v4.
